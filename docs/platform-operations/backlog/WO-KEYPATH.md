# WO-KEYPATH — service-role key-format divergence blocks headless function invocation

**Opened:** 2026-07-30 (surfaced regenerating the exec brief via the job-worker).
**Class:** infra / reliability. **Priority:** P2 (workaround exists: operator renders via UI).

## The finding

Invoking `generate-executive-report` (and any function that authenticates callers via
`getCallerIdentity`, `_shared/supabase-client.ts`) through the **job-worker** fails with
**HTTP 401 "invalid JWT ... signing method HS256 is invalid."**

Root cause — three service-role key representations have diverged:
- `getCallerIdentity` classifies a caller as `service_role` ONLY by exact string equality:
  `token === SUPABASE_SERVICE_ROLE_KEY` (now the **`sb_secret_*`** API-key format) or
  `token === get_current_service_role_key()` (vault value).
- The **job-worker** sends `SERVICE_ROLE_JWT` (the legacy **HS256 JWT**) as Bearer, because the
  platform `verify_jwt` gate on OTHER functions rejects the `sb_secret_*` format
  (`UNAUTHORIZED_INVALID_JWT_FORMAT`).
- So the job-worker's token equals none of the accepted values → falls through to
  `auth.getUser(token)` → GoTrue rejects the HS256 JWT under the project's asymmetric-key
  migration → 401.

Net: no internal (headless) caller can invoke a `getCallerIdentity`-gated, `verify_jwt=false`
function as `service_role`. The exec brief can only be generated by a **user** caller
(super_admin) — i.e. from the Reports UI.

## Options (pick one; needs operator go — credential-adjacent)

1. **Vault-key path in job-worker** — have the job-worker fetch and send
   `get_current_service_role_key()` (which `getCallerIdentity` already accepts) instead of
   `SERVICE_ROLE_JWT`. Contained, no auth-logic change.
2. **Dedicated internal-invocation seam** — a shared internal secret header (like
   `alert-delivery`'s `x-alert-delivery-internal`) that `getCallerIdentity` honors, so internal
   callers don't depend on service-role key format at all.
3. **Reconcile the three key values** so `SERVICE_ROLE_JWT` == `SUPABASE_SERVICE_ROLE_KEY` ==
   vault. Simplest to state, riskiest to rotate; do NOT do without an explicit go.

Do NOT paste JWTs in chat to test (standing rule). Until resolved: the exec brief / any
`getCallerIdentity` function is rendered from the UI (operator user session) or triggered by a
path that already holds the accepted key.
