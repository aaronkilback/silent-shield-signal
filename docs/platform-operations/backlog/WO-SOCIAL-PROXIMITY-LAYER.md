# WO-SOCIAL-PROXIMITY-LAYER — geography-anchored social, not keyword search (SCOPE, do not build)

**Requirement spec = the manual source set (operator, 2026-08-10).** During the Bald Range fire the operator collected household situational awareness **by hand from three sources** because Fortress gave nothing: (1) the **BC Wildfire app** (BCWS orders/alerts/active fires), (2) **NASA FIRMS** (satellite thermal — MODIS/VIIRS), (3) **social media**. Two of the three are now covered by `monitor-geo-wildfire`: BCWS (evac + fire) and CWFIS thermal hotspots (the same MODIS/VIIRS FIRMS reads). **The remaining gap is the social layer** — and it is where **perimeter behaviour, road closures, and evacuation-route conditions appear BEFORE official channels update.** That is exactly the information a household needs to decide *when* and *by which road* to leave.

## The honest constraint — this is NOT "turn social back on"
Keyword-based social search is a proven failure here: keyword social CSE was **deferred by ruling** (zero structural yield — [[project_social_monitor_dryup]]), and `monitor-instagram` has **never produced a signal**. So the question is **not** "re-enable keyword social." It is: **what would make a social layer work when the ANCHOR is geography rather than keywords?** The whole Phase-3 lesson applies — a keyword ("wildfire") is a global-noise magnet; a coordinate + radius is a filter. Social must be anchored the same way BCWS/CWFIS now are: to `client_geo_assets` proximity.

## What a proximity-anchored social layer would need
1. **Anchor on PLACE, not keyword.** Resolve a post to a location and test `ST_DWithin` to the client's assets — the same mechanism as the 788 re-exam (gazetteer place-name → coordinate → distance). Signal-worthiness = *near a client asset*, not *contains a keyword globally*. Fire-name tracking too (a post naming "Bald Range" once the fire is in the gazetteer).
2. **A geo-scoped SOURCE set, curated per region, not a global crawl.** Monitor the *local information ecosystem* around the client's coordinates: BCWS regional accounts, RDOS / district / First-Nations-band EmergencyInfo feeds, local news (Castanet/Penticton Herald for the Okanagan), DriveBC road-closure feed, and local emergency/community groups. This is a small, curated, authoritative set keyed to the assets — the opposite of a keyword firehose. **DriveBC (road closures) is arguably the single highest-value non-social feed here and is an official API, not social at all** — pull it out of "social" and cover it directly.
3. **Access reality (the hard part).** X/Twitter API is paid + geo largely deprecated; Facebook groups have no clean API (the real-time community layer lives here and is the hardest to reach); Reddit has an API (r/BCwildfire, local subs); Mastodon/Bluesky emerging. Scope must state the access cost/mechanism per platform honestly rather than assume.
4. **Credibility + corroboration.** Social is noisy and adversarial. A social claim (road X closed, fire jumped the highway) is a *lead*, corroborated against BCWS/DriveBC/CWFIS before it drives a severity, never emitted as authoritative on its own. (Complements [[WO-AUTHORITATIVE-SOURCE-PRECEDENCE]] from the other direction: social is the OPPOSITE of authoritative — it must be corroborated up, never trusted down.)
5. **Same output contract + proximity provenance** as `monitor-geo-wildfire`: which asset, distance, source, and a stated "quiet is quiet" so a silent social layer is distinguishable from a broken one.

## What it fills, concretely
The 4.3 km evacuation Order tells a household *there is an order*. The social/DriveBC layer tells them *Highway 97 is closed south of Summerland, the fire crossed the ridge at 3pm, the Kaleden exit is the open route* — the operational detail that governs the actual decision, and that official channels lag on. That is the third leg of the manual source set.

## Recommended first slice (when built)
Start with the **official, API-accessible, geo-anchorable** feeds that need no social access at all — **DriveBC road closures** (proximity to assets + routes) — then **Reddit local subs** (has an API), and treat true social (X/Facebook) as a later, corroboration-only lead layer. Highest value, lowest access cost, no repeat of the keyword-CSE / instagram dead ends.
