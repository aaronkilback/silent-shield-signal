# WO-GROUNDING-01 — Binding at Derivation (grounding, not just citability)

**Opened:** 2026-07-30. **Status:** OPEN — blocks ALL client-facing report issuance.
**Priority:** above WO-PROVENANCE-01 steps 4–7, WO-AGGREGATOR-RESOLVE-01, WO-SCOPE-EGRESS-01.

## Why
WO-PROVENANCE-01 made citations *checkable* (citability = is this publisher allowed).
That is orthogonal to *grounding* (does THIS signal support THIS claim). Making citations
checkable exposed a pre-existing class: **the model attaches a `[SIG]` id whose content does
not support the adjacent claim.**

- **Introduced by the rewiring (bug):** v2 `8dd2b9cb` action item 3 cited **SIG-2026-027390**
  (a wildfire evacuation rescue) for a **Uniper LNG** claim. Mechanism: enforcement removed the
  non-citable 027371 from the pool; the model reached for the nearest *citable* id.
- **Pre-existing (disclosure):** the "unsupported-by-any-signal" fabrication class predates the
  session — **SIG-2026-026745** (Alberta pipeline / killer whales) is cited for
  *"including … Petronas Canada [has stakes]"*; **no pool signal** ties Petronas to that pipeline.
  Present in the original `6027f0ac` and reproduced in v2.

## Item 5 finding — the retrospective audit is BOUNDED (logged as the finding)
Recoverable across the 154 PECL executive reports: `meta_json` citation refs (4–6 per report,
summary only), the signal pools (`signals` by window), and date ranges. **The rendered prose of
historical reports is UNRECOVERABLE** — reports were generated by direct invoke, HTML returned to
the caller, never persisted (`storage_url` null on all 154; no `function_jobs` row for most).
**Therefore the fabrication class cannot be bounded retrospectively.** That sentence is the finding.
(Closed forward by WO-REPORT-PERSIST-01: every new report now persists its HTML + a claim manifest.)

## Accepted design — Binding at Derivation (amended)
A claim is generated FROM a specific signal's content and carries that signal id as an intrinsic
property, not a later attachment. An assertion with no originating signal cannot be written.

1. Unit = `DerivedClaim { text, source_signal_ids[], source_span }`, produced from a bounded signal set.
2. Section prose is ASSEMBLED from bound claims; the narrative model orders/connects, never authors new facts.
3. No originating signal ⇒ cannot be written. Analytic lines are `Inference { text, over: [claim_ids] }`;
   empty `over` ⇒ rejected.
4. Flash + Summary obey the same rule.
5. Watchdog is defense-in-depth; grounding is decided at derivation.

### Amendment 6 — multi-signal factual claim
`DerivedClaim` binds **N** signal ids (`source_signal_ids: uuid[]`, ≥1) and stays **factual** (not
`Inference`). A claim corroborated by 3 outlets binds all 3 ids and remains a fact. `Inference` is
reserved for analysis that draws a conclusion NOT literally stated by any single signal.

### Amendment 7 — entity-scope guard (not string match)
Token match is insufficient both directions. Approach:
(a) **Alias resolution** — resolve client aliases (Petronas Canada Ltd / PECL / PCL / Progress Energy)
via the client entity's alias set, not raw string equality.
(b) **Implication without naming** — a signal that never names the client may still implicate it by
**asset proximity or operator relationship**, resolved against the **Gate-3 PostGIS asset points**
(spatial contains / distance to client-operated assets), not string search. A claim asserting client
impact must be backed EITHER by an alias hit in the source span OR by a resolved asset/operator link.
The 026745 failure = neither (no alias, no asset link to that Alberta pipeline) ⇒ rejected at derivation.

### Amendment 8 — Inference validity (anchor existence ≠ sufficiency)
An `Inference` is rejected unless its text **follows from** its `over` claims. Anchor existence is
necessary, not sufficient. Enforcement: an entailment check — the inference is re-derived from ONLY
its `over` claim texts in isolation; if a verifier cannot reconstruct the conclusion from those claims
alone (no outside facts), it is rejected. This is where DEDUCTIONS live and is the product's analytic
value — so the bar is entailment, not mere topical adjacency.
